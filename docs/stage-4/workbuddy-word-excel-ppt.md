# 用 WorkBuddy 搞定 Word、Excel、PPT：三个实测案例

装好 WorkBuddy、跑通第一个任务之后，真正的问题才开始：**日常工作里那些正经要交差的活，怎么交给它？**

办公室里最常见的三类交付物就是 Word 文档、Excel 分析、PPT。这篇用我们自己实测的三个任务，把每类活的指令怎么写、它怎么干、成品长什么样完整过一遍。三段指令取自开源的《WorkBuddy 实战蓝皮书》（一份社区共创、免费公开的实战手册，文末有链接），我们逐条实测跑通，都可以直接抄走，把文件名和场景换成你自己的。

## 派活公式：背景、产出、红线

**给 AI 派正经的活，一条合格的指令要交代齐三样东西：背景、产出、红线。**

给 AI 派日常小活，交代清楚"我是谁、做什么、用什么、出什么"就够了；但要交给领导、发给同事的正式交付物，还差一层：**你得告诉它什么不能做**。这就是三段式：

## 案例一：Word 方案，先出框架稿再定点修改

**场景：领导一句"你先出个团建方案"，最容易犯的错是闷头写一份二十页的细案。**方向还没定，写得越细废得越快。更稳的做法是分两步：先出一份**框架稿**（只列结构和要拍板的事，不填细节），拿去让领导定方向；方向定了，再让 AI 照着意见改出正式版。

### 第一步：一句话要一份框架稿

实测用的指令是这样的，背景（约 80 人）、产出（要哪几个板块）、红线（不要写得过于详细）都在里面：

```
帮我生成一份公司团建活动策划的 Word 文档框架。

公司约 80 人，包含：活动目标、活动主题建议、整体流程安排（含时间
节点）、分组与互动游戏建议、预算构成清单、人员分工、风险预案和
注意事项。

语言简洁实用，不需要写得过于详细，重点把整体框架和关键决策项列
清楚，适合直接拿去和领导确认活动方向。
```

它交出来一份 9 章、6 张表格的 Word 文档。最实用的一个细节：**所有需要领导拍板的事，它都用红色【待确认】标了出来**，最后一章还把这些待确认项收口成一张拍板清单，开会时对着这一页过就行：

![WorkBuddy 生成团建活动策划框架稿：左边是任务对话和文档结构汇报，右边是生成的 Word 文档，待确认项标红](/images/stage-4/2026-07-13/word-teambuilding-doc.png)
<div class="figcaption">左边是一句大白话进去、它汇报的文档结构（9 章 + 6 表格），右边是框架稿实际的样子：要领导拍板的事全部标红【待确认】。</div>

### 第二步：领导意见回来，定点修改

框架稿拿去汇报，方向定下来了：规模从 80 人改成 100 人、活动目标收成 3 条、流程表要加"所需物料"一列、预算要细化到单价……把这些意见发回给 WorkBuddy，加一条关键要求：**基于 V1 定点修改，输出 V2，不要重排全篇。**

为什么这条要写死？因为 AI 改文档有个烦人的毛病：你让它改一处，它顺手把全篇重写一遍，领导刚看过、已经点头的部分又变样了。"定点修改"就是只动该动的地方，其余原样保留。

改完它自己交了一份变更记录：改了什么、保留了什么、产物是哪两个文件，一目了然：

![WorkBuddy 输出的 V2 变更记录：修改内容六条、保留内容、产物两个文件](/images/stage-4/2026-07-13/word-changelog.png)
<div class="figcaption">V2 交付时附带的变更记录：目标压缩为 3 条、流程表改 5 列、预算总额 ¥48,400、风险预案重构为 4 类……验收时照单核对，不用逐页翻。</div>

这一来一回就是文档类任务的完整节奏：**框架稿 → 拿去拍板 → 带着意见定点修改 → 照变更记录验收**。通知、制度、总结、汇报材料，全是同一个套路。

## 案例二：Excel 分析，让结论可追溯

**场景：一份 7000 多行的电商销售数据，要做月度复盘**。数据分析是 WorkBuddy 这类工具最见功力的任务，也是指令质量差距最明显的任务：说"帮我分析下这个表"，它只能泛泛统计一通；把业务问题和红线说清楚，它交出来的就是能直接进复盘会的材料。

实测指令全文如下，值得整段抄走：

```
请读取 电商销售数据.xlsx，先不要修改原文件。

业务问题：分析本月各产品线的销售表现和盈利能力，判断哪些产品线
贡献高、哪些利润表现较弱，并识别本月销售过程中的异常波动。

请输出：
说明数据字段含义，并检查缺失值、重复记录、异常值和字段格式问题；
按产品线统计销售额、毛利、毛利率、销售额占比和毛利贡献占比，并
进行排名；
按日汇总销售额和毛利率，分析本月销售表现的日度变化；如果数据跨
度和完整性允许，再补充按周统计；
生成柱状图对比各产品线销售额和毛利，生成折线图展示本月每日销售
额变化；
识别销售额、毛利率或单笔订单金额明显异常的日期或记录，并结合数
据说明异常表现，不要在缺少依据时推测业务原因；
总结本月表现最好的产品线、需要重点关注的产品线，以及 3 条可直接
用于业务复盘的结论。

输出 output/sales-analysis.xlsx 和 output/summary.md。
要求：保留原始数据，统计过程和公式可追溯；图表标题直接表达主要
结论；无法从数据中确认的原因明确标注为待核实，不要自行编造。
```

> 💡 指令里反复出现的**毛利**和**毛利率**，是复盘最常用的两个数：卖出去的钱刨掉进货或生产成本，剩下的部分叫毛利；毛利占销售额的比例就是毛利率。毛利率低，意味着"卖得热闹但不怎么挣钱"。

这段指令里有两个动作，比任何技巧都值得学：

- **业务问题先行**。不是让它"分析数据"，而是告诉它这次分析要回答什么问题（哪些产品线贡献高、哪些弱、有什么异常）。它所有的统计和图表都会围着这几个问题转，而不是把能算的都算一遍堆给你。
- **把"不许编造"写进指令**。AI 分析数据最大的坑不是算错数，而是一本正经地替你编原因："11 月 18 日销售额下滑，可能是受天气影响。"数据里根本没有天气。指令里那句"不要在缺少依据时推测业务原因""无法确认的标注待核实"，就是专门堵这个口子的。

发出去之后它把任务拆成六步（读数据、质量检查、产品线统计、按日汇总、生成图表、异常识别与结论），逐项执行：

![Excel 分析任务发出后，WorkBuddy 把任务拆成六步的任务列表](/images/stage-4/2026-07-13/excel-analysis-task.png)
<div class="figcaption">指令发出后它列出的任务清单：六步和我们指令里的要求一一对应，执行到哪一步看得清清楚楚。</div>

8 分 39 秒后交活，4 个文件放进 output 文件夹。结论部分直接点到复盘会要讨论的事上：

![Excel 分析结果：数据概况、产品线排名表、结论，以及标题即结论的每日销售额折线图](/images/stage-4/2026-07-13/excel-analysis-result.png)
<div class="figcaption">交付的核心内容：全月 7,284 笔订单、总销售额 5.90 亿、毛利率 20.83%；床品件套销售额毛利双第一；厨房电器毛利率最低且利润贡献低于销售额占比，卖得多利润不成比例。右侧折线图的标题直接就是结论。</div>

注意右边那张折线图的标题：不是"11 月每日销售额变化图"，而是"11-11 峰值 0.28 亿，11-30 谷值 0.12 亿，毛利率围绕 20.8% 波动"。这就是指令里"图表标题直接表达主要结论"落地的样子，图不用人再看半天找重点。

这份产出放在多数团队里，就是一份合格的月度复盘初稿。剩下的活才真正需要人：核对关键数字，补上只有你知道的业务背景（比如 11 月 11 日的峰值是大促，数据里没写，你知道）。

## 案例三：PPT，只准用指定素材

**场景：要给管理层做一次 10 分钟的 AI Agent 主题分享，手头有一份现成的内容材料**。PPT 任务翻车的第一原因不是做得丑，而是不看对象：给管理层的片子塞满技术细节，给新人的片子全是黑话。所以这条指令把受众和时长放在最前面。

指令里的 `/ppt` 是**斜杠指令**：在输入框敲一个 `/` 可以调出已安装的技能（「AI Agent 使用」板块第九章讲过的那种"能力包"），`/ppt` 就是点名让 PPT 技能来接这个活，做出来的片子比裸做要专业。

```
/ppt 请根据当前工作区材料制作一份 8 页以内的 AI Agent 主题分享 PPT。
受众：对 AI 有基础认知，但不了解 Agent 的业务和管理人员。
汇报时长：10 分钟。

目标：让听众理解 AI Agent 是什么、与普通 AI 对话工具有什么区别、
能解决哪些问题，以及企业应该如何判断是否值得落地。
素材：
AI术语全景手册.md 是主要内容材料；
不要补充工作区材料之外的事实和数据。
全文控制在 8 页以内，每页只表达一个核心结论；
案例、数据和关键判断必须标注素材来源，无法确认的内容不要自行补充；
PPT 标题尽量直接表达观点，不使用 AI Agent 介绍、应用场景这类泛化
标题；
输出 output/ai_agent.pptx。
```

这条指令的红线比前两个案例更严：**只准用工作区里那份《AI术语全景手册.md》，不许补充材料之外的事实**。为什么？因为分享场合的每一页都可能被当场追问，AI 从别处"补充"来的数据你没核实过，被问住就下不来台。宁可片子薄一点，也要保证每句话都有出处。

> 💡 **工作区**是「AI Agent 使用」板块讲过的概念，就是这个任务的"项目文件夹"：素材放进去，它读文件、存成品都在里面。

执行过程里有个值得一看的细节：它先检查工作区，发现指令里提到的素材文件不在原位，**自己动手搜索、找到了文件、读完接着干**，没有停下来把问题抛回给你：

![/ppt 指令发出后，WorkBuddy 发现素材文件不在原位，自己搜索定位并读取了 AI 术语全景手册](/images/stage-4/2026-07-13/ppt-task.png)
<div class="figcaption">指令、受众、素材范围、红线都交代在一条消息里。中间的执行记录：工作区看着是空的，它自己搜到了素材文件并读取，这是 Agent 和普通聊天 AI 的典型区别。</div>

最后交付的就是指令里指定的 `output/ai_agent.pptx`，8 页以内、每页一个结论。

一个截图里能看到的提醒：这次实测权限开的是"允许完全访问"（输入框左下角红字），它全程不会停下来问你。**新手建议保持默认权限**，让它在高风险操作前先问一声，等你对它有信心了再开完全访问。

## 进阶：一条指令要一个"交付包"

**三件套真正的威力是联动：一场会开完，Word、Excel、PPT 一次全要**。比如一次产品评审会，会上有决策、有待办、有下版本计划。会后的常规做法是手工整理纪要、补需求文档、做任务表、再做汇报 PPT，四样东西各做各的，数字和排期还容易对不上。交给 WorkBuddy 可以一条指令要齐（前提是把会议转写或纪要文件放进工作区）：

```
请读取本次产品评审会议的转写和纪要，生成一个办公交付包。
目标：把会议内容转成可以推进研发的材料。
请输出：
1. Word：output/feature-prd.docx，包含背景、目标用户、核心问题、
   需求列表、验收标准、风险和待确认问题；
2. Excel：output/action-items.xlsx，字段包含事项、负责人、优先级、
   截止日期、状态、验收标准；
3. PPT：output/review-summary.pptx，6 页以内，面向管理层，突出本次
   会议决议、资源请求和风险。
约束：
- 会议中没有明确确认的内容，不要写成既定结论；
- 人名、日期、功能范围必须保留来源；
- 如果缺少负责人或时间，标为待确认；
- 先输出大纲和任务表字段预览，等我确认后再生成文件。
```

说明一下：前面三个案例是我们逐条实测跑通的，这条联动指令是蓝皮书给出的模板，我们原样放在这里，结构和前三条是同一个路数，按你自己的会议材料改了就能用。

最值得学的是最后一条约束：**先出大纲和字段预览，确认后再生成文件**。一次要三样交付物，任何一样口径歪了都是三倍返工，把确认环节挪到生成之前，成本最低。而三样东西出自同一场会议、同一条指令，人名、数字、排期同源，不会出现"PPT 里的排期和任务表对不上"这种经典事故。
